# M2.5 verification — root stack declarations and script inventory

## Implemented

Explicit project inspection now adds a transient stack observation with timestamp,
detector version, source-specific declarations and fixed diagnostic codes. Root
Maven properties/compiler configuration, simple project.requires-python and
.python-version are supported. Conflicts/expressions are displayed without
resolution. Potential script filenames are listed at root and directly in scripts/.
No process, build, Python import, script-content read or network operation is used
by this detector. The existing independent Git observation still uses trusted Git.

Secure XML, bounded file reads, no-follow paths, shallow bounded enumeration and
escaped output retain the project's read-only guarantees. Domain/detection/engine
remain Spring-free. No dependency, storage schema or backup format changes.

## CI and boundaries

The PR records the actual Java 21 Ubuntu/Windows clean-verify outcomes and run
link. Platform-specific tests skip only where the relevant OS capability is absent.
Runnable JARs and test/coverage reports are CI artifacts.

R10 remains partial: root manifests only; no effective Maven model, inherited or
module-specific versions, Poetry parser, dependencies, installed runtimes, dynamic
Python metadata or script execution. Python extraction is lexical, not full TOML
validation. Unknown versions are explicitly unknown. Each manifest is capped at
256 KiB, XML nesting at 64, script enumeration at 200 entries and a cooperative
5-second deadline. Filesystem blocking/races retain the existing stable-tree limits.

The prior intermittent Windows H2 reopen incident is not claimed fixed. Its safe
diagnostics and 30-reopen regression remain. Interaction history, backup confidence,
recommendations/local issue drafts and fuller stack inference remain M2 work.
