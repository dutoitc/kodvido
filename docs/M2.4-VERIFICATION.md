# M2.4 verification — catalogue JSON backup/import

## Implemented

Version 1 local JSON download; strict bounded upload; preview including notes;
editable native destination paths; explicit confirmation; atomic insert-only
restoration preserving project IDs, names, timestamps and workflow revisions.
A serializable database snapshot keeps project and workflow data together.
Missing folders are supported without reading, creating or writing project files.
Conflicts roll back the entire batch. UI actions retain CSRF protection and escaping.
No additional dependencies or schema migration; Spring/Jackson remain in app.

## Limits and remaining work

- JSON is unencrypted local metadata containing paths and declared notes. No
  project files or transient observations are included; this is not a shareable
  sanitized M3 report or proof that projects/data are backed up.
- Maximum 1000 projects / 8 MiB JSON. Oversized downloads fail rather than truncate.
- Existing entries cannot be overwritten or selectively merged. Correct foreign
  paths manually; lexical normalization does not identify filesystem aliases.
- Preview is in memory, one per application, expires after 30 minutes; restarting
  or uploading another valid preview requires reviewing the backup again.
- The prior intermittent Windows H2 reopen failure is still not diagnosed. Safe
  SQL state/vendor diagnostics and the existing 30-reopen regression remain.
- Interaction history, stack/script evidence, backup confidence, recommendations
  and sanitized local issue drafts remain M2 work. M3 remains unstarted.

Changed areas: domain transfer record/port, engine backup use case, JDBC adapter
and connection-scoped workflow reader, app controller/configuration/templates,
three test suites plus stage expectation, README/roadmap/ADR/this report, and
ignore rule for standard private catalogue download filenames.
