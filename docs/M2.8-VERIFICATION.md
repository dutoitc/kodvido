# M2.8 — Suggestions and local detector-gap drafts

## Implemented

R14: deterministic suggestion cards based on current observation statuses, missing
restart text, UNKNOWN backups and declared backup failures. NOT_OBSERVED remains
distinct from MISSING/FAILED. No score or verified-safe conclusion, inferred work
activity, stale-date policy, automatic command, update or repair.

R18: local Markdown drafts for FILES/GIT/STACK with PARTIAL, UNKNOWN, UNSUPPORTED
or FAILED status. MISSING/SUPPORTED have no gap draft. Generation accepts enums
only; it cannot receive project paths, IDs, names, source text, script names, notes,
raw diagnostics or runtime-version declarations. The template requests a synthetic
reproduction and manual review of any additions. It does not prove a detector bug.

Drafts display after explicit inspection and download through a CSRF-protected POST.
Downloads have a fixed filename, text/markdown UTF-8 type and no-store caching;
invalid enums are rejected without reflecting input. No new scan, catalogue/event
write, project-file change or remote submission is triggered by download. GET project
pages do not scan; all observations and drafts remain transient. Domain/engine are
Spring-free; app adapters own French presentation. No new dependencies or migration.

## Scope and next acceptance

The draft is intentionally generic: it carries no actual diagnostic detail or
reproduction data. Users may add a synthetic fixture manually, reviewing it before
sharing. Suggestions are a bounded initial policy, not project auditing or backup
verification. Root-only stack declarations and existing detector exclusions remain.
No persistence of observations/drafts or external issue integration is implemented.

The dependent PR must follow PR #8. Its import/export simplification deliberately
uses one unversioned current JSON format (ADR-017), without legacy compatibility.
